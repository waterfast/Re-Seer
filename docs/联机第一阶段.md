# 战斗联机第一阶段

本阶段接通 Unity → C++ Asio → Lua 5.4 的真实通信：本机玩家对 Lua AI，固定联调阵容。
收到快照后显示双方精灵和体力；普通技能、第五技能点击发送操作意图；Lua 结算伤害和 PP；
Unity 根据确认数据刷新血条、技能槽和伤害数字；战斗结束显示胜负并锁定按钮。

联调精灵沿用 4500 / 4260 的现有素材，数值和技能使用演示配置，不代表官方战斗规则。
普通槽为 `demo_thunder`、`demo_break`、`demo_focus`，第五技能为 `demo_spark`。
技能威力、命中、最大 PP 和目标与客户端演示技能库对应。

## 开始体验

Windows 本机需要 Python 3.12+、CMake，以及 PATH 中的 GCC / MinGW 工具链。
构建工具下载固定版本的 Asio 1.30.2、nlohmann/json 3.11.3、Lua 5.4.7，
放进被 Git 忽略的 `Server/seer-asio/.deps`，不会修改系统 Lua。

在项目根目录运行：

```powershell
python tools/build_battle_server.py
powershell -ExecutionPolicy Bypass -File tools/start_battle_server.ps1
```

然后在 Unity 打开 `Assets/Scenes/BattleNetwork.unity`，进入 Play。
顶部显示连接状态与当前回合，点击技能即可对战；结束后可点“再战一局”。
启动失败时检查服务器是否在运行，再点“重新连接”。服务器仅监听 `127.0.0.1:9527`。

`Battle.unity` 保留原来的 UI 演示。独立的 `BattleNetwork.unity` 已关闭本地测试数据源自动启动
和扣血快捷键；网络组件显式绑定 UI、操作区与技能库。
`python tools/prepare_battle_network_scene.py` 可以从当前 Battle 布局重新生成联机场景，
会覆盖联机场景自身的手工修改。

## 职责和消息

```text
FramedJsonConnection（TCP 分帧、收发队列）
    ↓ Unity 主线程 Pump
BattleNetworkController（握手、请求对应、输入锁定、错误处理）
    ↓
BattleSnapshotState（校验、序号去重、确认状态）
    ↓
BattleContext / BattleUiDataState → BattleUIController
```

外部传输为 4 字节无符号大端长度 + UTF-8 JSON；长度为正文的字节数，不包含头部。
单帧限制 64 KiB。接收器必须读满头和正文；不截断消息、不按一次读取划分消息。
消息采用 JSON-RPC 2.0 结构，本阶段只接受正整数请求 ID 和对象参数，不支持批量请求。

| 消息 | 方向 | 含义 |
| --- | --- | --- |
| `session.hello` | Unity → C++ | 返回协议版本 1 与本机演示玩家 ID |
| `battle.start` | Unity → C++ | C++ 新建私有 Lua 战斗进程，使用服务器固定阵容 |
| `battle.action` | Unity → C++ | 携带 battleId、promptId、技能 ID、目标精灵实例 ID |
| `battle.snapshot` | Unity → C++ | 获取当前连接已有战斗的快照 |
| `battle.update` | C++ → Unity | 无 id 的通知：确认快照、表现事件、下一次询问或胜负 |
| 同 id 响应 | C++ → Unity | 操作接收结果或结构化错误 |

C++ → Lua 保留现有 stdin/stdout 逐行 JSON-RPC：`clientStartGame`、`clientAction`、
`clientSnapshot` 是客户端适配方法，内部调用原有 startGame / runGame / handlePlayerAction。
C++ 等待 RPC 响应时持续读取 Lua 的 `notifyPlayers` 通知，把事件与确认快照组成一次更新。
Lua 的 stdout 只发送协议，日志走 stderr。

玩家身份、房间编号由 C++ 根据连接指定；客户端传入这两个字段会被覆盖。
Lua 校验当前询问属于玩家、技能可用、目标合法。玩家 ID、阵营、精灵座位彼此有明确映射。
`petId` 是战斗实例编号，`speciesId` 才是头像和立绘素材编号。

`promptId` 对应这次行动询问。重复提交同一选择返回当前快照，不再次执行规则或扣 PP；
过期询问、重复询问的不同选择、非法目标和其他战斗编号返回错误。
`sequence` 是确认状态版本，Unity 忽略重复或更旧的更新，也不会重复播放伤害数字。

HP 使用服务器给出的绝对值更新 `BattlePetState` / `BattleUiDataState`，事件只调用
`ShowNumber`。不会再调用会扣血的 `TakeDamage`，因此不会双重扣血。
点击时只锁定技能，不预测伤害或 PP；服务端的新快照决定何时重新开放输入。
网络收发不接触 Unity 对象，所有 JSON 解码和 UI 更新都在主线程完成。

## 后续范围

本阶段每条连接对应一场独立战斗，对手为 Lua AI；关闭连接会回收该场 Lua 进程。
“重新连接”开始新战斗，尚不支持断线后恢复旧对局。
未接入账户、两名真人匹配、换精灵、道具、逃跑、持久化与完整战斗动画队列。
C++ 暂用独立连接线程串行处理本房间，隔离 Lua 的阻塞调用；房间增多后再迁移到异步管道桥接。
